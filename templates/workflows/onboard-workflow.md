## ONBOARD WORKFLOW (LEGACY PROJECT → RULES + SKILLS + SPEC)
When executing the [>om-scan] command, you MUST act as a Senior Solutions Architect reverse-engineering an existing codebase. Follow this 3-phase process strictly.

**Pre-check:** If `.omni/onboard-report.json` does NOT exist, STOP immediately:
```
❌ Chưa có onboard report. Chạy trong terminal trước:
   omni onboard
```

**Phase 1: Read & Display**

Read `.omni/onboard-report.json` and display a structured summary:

```
📋 Tôi đã scan dự án của bạn:
   • Stack: [techStack.language] + [techStack.framework] + [techStack.ui]
   • Quy mô: [stats.loc] LOC, [stats.files] files
   • Conventions: [conventions.linter], [conventions.formatter], [conventions.commitConvention]
   • Code style: [codePatterns.naming.files] files, [codePatterns.imports.style] imports
   • Tests: [techStack.test] ([codePatterns.testPatterns.location])
   • Structure: [structure.type]
   • Issues: [landmines.count] landmines

Tôi sẽ hỏi vài câu để hiểu thêm những gì không thấy trong code.
```

**Phase 2: AI Interview (5-8 câu adaptive)**

Ask questions ONE AT A TIME. Prefer multiple-choice format.

**Nhóm 1: Context (luôn hỏi, 2-3 câu)**

| # | Target | Câu hỏi |
|---|--------|---------|
| 1 | Business context | "Dự án này phục vụ ai? Mục tiêu chính là gì? (a) SaaS product (b) Internal tool (c) Open-source (d) Client project" |
| 2 | Team & process | "Mấy người làm việc trên repo này? (a) Solo dev (b) Small team, PR review (c) Large team, CI gate (d) Open-source, external PRs" |
| 3 | Current state | "Dự án đang ở giai đoạn nào? (a) Active development (b) Maintenance mode (c) Đang refactor/migrate (d) Legacy, ít thay đổi" |

**Nhóm 2: Conventions (adaptive — chỉ hỏi khi scan phát hiện ambiguity)**

- If `codePatterns.naming.files` is "mixed" → ask about naming standard
- If `codePatterns.testPatterns.location` is "none" → ask about test policy
- If `landmines.count` > 5 → ask about tech debt strategy
- If `structure.type` is "monorepo" → ask about sub-project boundaries

**Nhóm 3: Preferences (1-2 câu)**

| # | Target | Câu hỏi |
|---|--------|---------|
| 6 | Coding style | "Khi AI viết code mới, style nên: (a) Match existing code exactly (b) Existing + improvements (c) Best practices, dù khác code cũ" |
| 7 | Forbidden patterns | "Có pattern/library nào team muốn TRÁNH? (Gõ tự do hoặc 'không có')" |
| 8 | Priority | "Phần nào cần chú ý nhất? (a) Performance (b) Security (c) Code quality (d) Feature velocity" |

**Adaptive rules:**
- Minimum 5 questions, maximum 8
- Skip nhóm 2 entirely if no ambiguity detected in scan
- After each answer, re-evaluate: enough info to generate? If yes → proceed to Phase 3
- Each question must have: description (why needed), format hint, 2-3 examples

**Phase 3: Generate Outputs**

Generate 4 files based on scan data + interview answers:

**Rules:**
- Do NOT write any application code. Only generate rules, skills, specs, and task files.
- Do NOT skip Phase 2 interview — always ask at least 5 questions.
- If onboard-report.json is malformed or missing required fields, tell user to re-run `omni onboard --refresh`.
- Keep generated files concise — aim for quality over quantity.
